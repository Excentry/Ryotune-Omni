# Distribución práctica de fuentes de libmpv para Windows

Notas de investigación, 21-10-2026. Alcance: redistribución de la DLL GPL con dependencias estáticas; no certificación jurídica ni dictamen profesional. La FAQ GNU y FFmpeg también advierten que sus explicaciones no son asesoramiento jurídico. Se leyeron los documentos locales actuales; no se reconstruyó la DLL ni se verificó independientemente todo el contenido del contenedor. [FAQ GNU](https://www.gnu.org/licenses/gpl-faq.html); [FFmpeg Legal](https://ffmpeg.org/legal.html).

## 1. ¿Podemos distribuir el binario oficial mediante enlaces o una oferta escrita?

### Takeaway

Sí puede conservarse el binario oficial **si** se consigue su Corresponding Source completo y se ofrece mediante una modalidad aplicable de GPLv3 §6. Enlazar archivos de terceros puede satisfacer §6(d); enlazar únicamente fuentes parciales o un contenedor de compilación no demuestra ese cumplimiento. [GPLv3 §§1,6](https://www.gnu.org/licenses/gpl-3.0.html#section6).

### Cited Findings

- Redistribuir sin modificar no elimina la obligación de fuentes: GNU responde expresamente que quien descarga un binario y lo redistribuye también debe distribuir las fuentes correspondientes completas; la excepción de oferta recibida es limitada. [FAQ: UnchangedJustBinary](https://www.gnu.org/licenses/gpl-faq.html#UnchangedJustBinary).
- Para descarga de binarios, §6(d) permite fuentes en otro servidor, propio o de terceros, con facilidades equivalentes de copia, sin cargo adicional, e instrucciones claras **junto al binario**. El redistribuidor sigue obligado a asegurar disponibilidad durante el tiempo necesario; GNU lo explica, como mínimo, mientras distribuye el objeto. No exige descargar las fuentes obligatoriamente con el instalador. [GPLv3 §6(d)](https://www.gnu.org/licenses/gpl-3.0.html#section6); [FAQ: servidores distintos](https://www.gnu.org/licenses/gpl-faq.html#SourceAndBinaryOnDifferentSites); [FAQ: descarga opcional](https://www.gnu.org/licenses/gpl-faq.html#HowCanIMakeSureEachDownloadGetsSource).
- Un repositorio de control de versiones puede servir, pero el checkout no debe ser gravoso o restrictivo: instrucciones claras y convenientes deben recuperar las fuentes del objeto concreto, no simplemente HEAD. Un archivo descargable completo reduce esta fragilidad. [FAQ: SourceInCVS](https://www.gnu.org/licenses/gpl-faq.html#SourceInCVS).
- §6(b) contempla una oferta escrita al entregar el objeto en un producto físico, incluido un medio físico: válida al menos tres años y mientras se ofrezcan repuestos o soporte para ese modelo; beneficia a cualquiera que posea el objeto. Permite entregar fuentes en medio durable con coste físico razonable, o acceso de red gratuito. No es una alternativa genérica para publicar una descarga con «fuentes bajo petición». [GPLv3 §6(b)](https://www.gnu.org/licenses/gpl-3.0.html#section6); [FAQ: AnonFTPAndSendSources](https://www.gnu.org/licenses/gpl-faq.html#AnonFTPAndSendSources).
- §6(c) permite transmitir una oferta recibida conforme a §6(b) solamente ocasionalmente y sin carácter comercial. No debe asumirse aplicable a las publicaciones ordinarias del proyecto. [GPLv3 §6(c)](https://www.gnu.org/licenses/gpl-3.0.html#section6).
- Una oferta no reemplaza el contenido debido: promete entregar el Corresponding Source completo. Si no puede satisfacerse la licencia, §12 no permite distribuir ignorando esa obligación. [GPLv3 §§6,12](https://www.gnu.org/licenses/gpl-3.0.html#section12).
- El inventario local identifica el artefacto `libmpv-v0.41.0-dev-ga43ab319f-39541010475-x86_64-w64-mingw32-gpl.zip`, DLL SHA-256 `5816ca7aeab4d07774f3b26c465ee6691c41660ba7288381949413c9844bcdf7`, fuentes de mpv y FFmpeg solamente parciales e inventario estático incompleto. Esto es evidencia del proyecto, no una auditoría independiente del upstream. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md); [run upstream identificado](https://github.com/mpv-player/mpv/actions/runs/39541010475).

### Inferences

- Para esta DLL, **todavía no hay base documental suficiente para levantar el bloqueo de redistribución**: la ausencia de fuentes transitivas identificadas no se resuelve con un enlace genérico a mpv/FFmpeg, una etiqueta GPL ni una promesa de obtenerlas después. Es una conclusión prudencial sobre la evidencia disponible, no una acusación de infracción al upstream. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md); [GPLv3 §§1,6](https://www.gnu.org/licenses/gpl-3.0.html#section1).
- Un contenedor podría transportar fuentes suficientes si realmente las conserva, junto con cambios y scripts necesarios, en formato accesible. Su digest sólo identifica bytes de una imagen; **no prueba que incluya esas fuentes**. Bibliotecas `.a`, cabeceras, paquetes instalados y scripts que descargan HEAD no sustituyen el código preferido para modificar cada componente incluido. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1).
- Método recomendado: archivos completos e inmutables de fuentes en la misma publicación del binario, con manifiesto y sumas; copia de respaldo bajo control del proyecto. Hosting ajeno es jurídicamente posible bajo §6(d), pero la responsabilidad no se delega al proveedor. Esto es una medida operativa, no una exigencia de alojarlo todo en un único servidor. [GPLv3 §6(d)](https://www.gnu.org/licenses/gpl-3.0.html#section6).

### Gaps

- No se comprobó que el upstream haya publicado posteriormente un paquete completo para ese run. Las notas parten del estado descrito en la auditoría local; no concluyen inexistencia universal de las fuentes. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md).
- No se evaluaron contratos concretos de hosting, jurisdicción, patentes ni una transacción de User Product. La duración y modalidades aplicables requieren revisar el canal real de distribución. [GPLv3 §6](https://www.gnu.org/licenses/gpl-3.0.html#section6); [FFmpeg: patentes](https://ffmpeg.org/legal.html).

## 2. ¿Qué fuentes deben corresponder y qué puede excluirse?

### Takeaway

Se necesitan las fuentes efectivamente utilizadas, sus modificaciones y los scripts necesarios para generar, instalar y modificar el trabajo; **no** se exige producir una DLL con hash idéntico. Las exclusiones de bibliotecas de sistema y herramientas tienen criterios concretos: no amparan automáticamente los codecs estáticos ni todo lo que haya dentro de una imagen de compilación. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1); [FAQ: hash exacto](https://www.gnu.org/licenses/gpl-faq.html#MustSourceBuildToMatchExactHashOfBinary).

### Cited Findings

- §1 define Corresponding Source como todo el código necesario para generar, instalar, ejecutar el objeto ejecutable y modificarlo, incluidos scripts de control e interfaces asociadas. Excluye material que pueda regenerarse automáticamente desde otras partes del propio Corresponding Source. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1).
- GNU distingue correspondencia y reproducibilidad bit por bit: deben ser las fuentes de las que se hicieron los binarios, aunque timestamps o versiones del compilador impidan reproducir su hash exacto. Esto no autoriza sustituirlas por una versión anterior o posterior. [FAQ: hash exacto](https://www.gnu.org/licenses/gpl-faq.html#MustSourceBuildToMatchExactHashOfBinary); [FAQ: versión exacta](https://www.gnu.org/licenses/gpl-faq.html#AnonFTPAndSendSources).
- La excepción System Libraries requiere ambos elementos de §1: inclusión en la forma normal de empaquetar un Major Component, sin formar parte de él, y función limitada a permitir usarlo con ese componente o implementar una Standard Interface con implementación pública en fuentes. Major Component incluye kernel, sistema de ventanas, compilador o intérprete. No significa «cualquier dependencia común». [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1); [FAQ: SystemLibraryException](https://www.gnu.org/licenses/gpl-faq.html#SystemLibraryException).
- También se excluyen herramientas de propósito general o programas libres generalmente disponibles, utilizados **sin modificar** y que no formen parte del trabajo. Esto puede excluir herramientas de construcción en esas condiciones; no excluye los scripts específicos que gobiernan la construcción ni código de bibliotecas incorporado al objeto por el mero hecho de proceder del toolchain. Evaluar runtimes y excepciones propias por separado. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1).
- La FAQ GNU considera que enlace estático o dinámico con módulos no cambia por sí mismo el alcance de la GPL sobre la combinación. La exclusión de bibliotecas de sistema sigue siendo un análisis separado. [FAQ: GPLStaticVsDynamic](https://www.gnu.org/licenses/gpl-faq.html#GPLStaticVsDynamic); [FAQ: SystemLibraryException](https://www.gnu.org/licenses/gpl-faq.html#SystemLibraryException).
- FFmpeg indica que activar componentes GPL hace aplicable la GPL a todo FFmpeg. Su checklist, expresamente orientado a una vía sencilla de cumplimiento **LGPL**, pide fuentes exactamente correspondientes, cambios, explicación de compilación/configure, archivo tar/zip y revisión de bibliotecas externas; no debe trasladarse mecánicamente su texto «LGPLv2.1» a este build GPL. [FFmpeg Legal](https://ffmpeg.org/legal.html).
- Una variante LGPL tampoco suprime las fuentes de bibliotecas distribuidas. GNU explica obligaciones de fuentes y re-enlace; LGPLv3 §4 permite, según el caso, código adecuado para recombinar/re-enlazar o un mecanismo compartido apto para bibliotecas modificadas compatibles. Deben revisarse versión concreta de LGPL y todas las dependencias, no sólo el nombre del asset. [FAQ: LGPLStaticVsDynamic](https://www.gnu.org/licenses/gpl-faq.html#LGPLStaticVsDynamic); [LGPLv3 §4](https://www.gnu.org/licenses/lgpl-3.0.html#section4).

### Inferences

- Fecha de un tarball, commit «más cercano» al run o nombre de versión permiten buscar candidatos, pero no prueban cuál se compiló ni descartan parches, cachés, wraps o ramas móviles. Falta un vínculo verificable entre artefacto, revisión y modificaciones; no falta necesariamente reproducibilidad bit por bit. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md); [FAQ: hash exacto](https://www.gnu.org/licenses/gpl-faq.html#MustSourceBuildToMatchExactHashOfBinary).
- Un archivo de fuente upstream sin cambios puede servir si se acredita que fue el utilizado. SHA-256 acredita integridad del archivo conocido, no su relación histórica con la DLL. Commits, hashes y manifiestos son evidencia operativa recomendada, no formatos jurídicos exigidos literalmente por GPLv3. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1); [FFmpeg Legal](https://ffmpeg.org/legal.html).
- Cambiar a un build llamado LGPL no arregla automáticamente los huecos: requeriría otro artefacto, configuración sin componentes incompatibles, fuentes correspondientes y obligaciones de las bibliotecas estáticas que permanezcan. Tampoco cambia por sí solo la licencia GPL del proyecto anfitrión. [FFmpeg Legal](https://ffmpeg.org/legal.html); [Licencias del proyecto](../../../LICENSING.md).

### Gaps

- No hay aquí una clasificación cerrada de MinGW, runtimes, C++/WinRT, SDK, codecs o recursos concretos como excluidos/incluidos. Se necesita inventario de lo efectivamente incorporado y licencias/excepciones de cada elemento; no es correcto exigir fuentes de todo el sistema operativo o dispensar todo el contenedor. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1).

## 3. ¿Qué ruta práctica y criterios finitos permiten cerrar el bloqueo?

### Takeaway

Primera opción: solicitar al upstream un paquete y manifiesto completos para el run exacto, validarlos y conservarlos con la publicación. Si no se recuperan entradas históricas, reemplazar la DLL por un build de entradas íntegramente fijadas que emita sus fuentes y avisos; no reconstruir retrospectivamente revisiones por aproximación. Es una recomendación operativa derivada del requisito de correspondencia. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md); [GPLv3 §§1,6](https://www.gnu.org/licenses/gpl-3.0.html#section6).

### Cited Findings

Checklist de aceptación propuesto. Los formatos de evidencia y el ensayo de compilación son controles prácticos del proyecto, no condiciones textuales adicionales de la GPL:

1. **Identidad:** registrar archivo original, SHA-256 de ZIP y DLL, arquitectura, opciones GPL/version3, run y digest de imagen; asociarlos inequívocamente al paquete de fuentes. No aceptar coincidencia de fecha como única evidencia. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md); [FAQ: versión exacta](https://www.gnu.org/licenses/gpl-faq.html#AnonFTPAndSendSources).
2. **Inventario cerrado:** enumerar componentes realmente enlazados, incluidos transitivos estáticos, código vendorizado, submódulos, Meson wraps y recursos incorporados; para cada uno: revisión/archivo exacto, hash, licencia, parches o declaración de ausencia de cambios. Distinguir componentes sólo presentes en imagen de los incorporados a la DLL. Justificar cada exclusión System Library/herramienta, no dejar «dependencias varias» sin resolver. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1).
3. **Contenido:** almacenar fuentes completas en forma preferida para modificar, base y parches aplicables o árbol ya parcheado, interfaces y material no regenerable necesario. Ni sólo diffs, ni objetos `.a`, ni cabeceras sustituyen ese conjunto. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1); [FAQ: fuentes completas](https://www.gnu.org/licenses/gpl-faq.html#DistributingSourceIsInconvenient).
4. **Construcción e instalación:** incluir recetas del run, Dockerfiles/scripts necesarios, órdenes/configure/Meson, parches, resolución de subproyectos y pasos de instalación; documentar herramientas/versiones y requisitos externos excluidos. Ninguna descarga necesaria de fuentes cubiertas debe quedar en HEAD sin fijar. [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1); [FFmpeg Legal](https://ffmpeg.org/legal.html).
5. **Prueba técnica:** extraer en entorno limpio y verificar manifiesto/hashes; ensayar generación e instalación con el paquete, comprobar funciones/configuración relevantes y registrar divergencias. Una diferencia de hash de DLL por timestamps no es rechazo automático; una fuente ausente o parche desconocido sí deja el criterio incompleto. Esta prueba no certifica cumplimiento jurídico. [FAQ: hash exacto](https://www.gnu.org/licenses/gpl-faq.html#MustSourceBuildToMatchExactHashOfBinary).
6. **Avisos:** conservar copyrights, licencias completas, ausencia de garantía, atribuciones y condiciones adicionales aplicables; identificar cambios y fechas cuando corresponda. Revisar avisos por componente/archivo y avisos de interfaz aplicables, no sólo LICENSE de mpv/FFmpeg ni pantalla del instalador. Incorporar índice comprensible de licencias y fuentes. [GPLv3 §§4,5,7](https://www.gnu.org/licenses/gpl-3.0.html#section4); [FAQ: incluir licencia](https://www.gnu.org/licenses/gpl-faq.html#WhyMustIInclude); [Auditoría local de avisos](../../LIBMPV-SOURCE-AUDIT.md).
7. **Publicación:** ofrecer binario y archivo completo de fuentes mediante §6(d), instrucciones contiguas al enlace del binario, sin cargo adicional y acceso equivalente. Comprobar descarga real, formato públicamente documentado, sin clave especial para extraer/leer/copiar; mantener copia y disponibilidad de cada versión publicada. No confundir política interna de retención con la oferta mínima de tres años de §6(b), que es otra modalidad. [GPLv3 §6](https://www.gnu.org/licenses/gpl-3.0.html#section6).
8. **Cierre documentado:** no publicar con casillas abiertas sobre correspondencia, licencias incompatibles o fuentes faltantes. Registrar revisión de Installation Information si la transacción entra en User Product y de restricciones de EULA/canal. El cierre del checklist autoriza una decisión interna informada, no una certificación legal. [GPLv3 §§6,10,12](https://www.gnu.org/licenses/gpl-3.0.html#section6).

### Inferences

Contenido de una solicitud al upstream, **sin enviarla**:

- Identificar ZIP, sus hashes, DLL, commit mpv `a43ab319fdb7aec31874999e5562c9975328cbda`, FFmpeg `ca85613d10cd523dd05780f48dc6ecac142bd560`, run `39541010475` e imagen `ghcr.io/btbn/ffmpeg-builds/win64-gpl@sha256:666d6b74870f232bbc9ea29acc608c91b6b1c74f1effd8129cd39ed2332d1287`. Pedir confirmación de asociación, no sólo «fuentes de la última versión». [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md).
- Pedir archivo completo de Corresponding Source, manifiesto de dependencias estáticas realmente usadas y revisiones/hashes; parches locales, entradas de caché, wraps, submódulos y recetas exactas tanto de mpv como de la imagen FFmpeg; evidencia de resolución de LuaJIT `v2.1`, libsixel, subrandr, MuJS/WrapDB y subproyectos Meson. Pedir licencias y avisos de todos los componentes y las exclusiones justificadas. Son los huecos concretos identificados localmente frente a GPLv3 §1. [Auditoría local](../../LIBMPV-SOURCE-AUDIT.md); [GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.html#section1).
- Preguntar si conservan el árbol fuente/archivo de ese run o dónde descargarlo, y si permiten resolver la correspondencia con evidencia del build. No pedir una reconstrucción con hash idéntico como condición jurídica; sí fuentes realmente usadas y scripts requeridos. [FAQ: hash exacto](https://www.gnu.org/licenses/gpl-faq.html#MustSourceBuildToMatchExactHashOfBinary).
- Si no quedan esas entradas, escalar al propietario del pipeline nativo para **otro build** con entradas fijadas y archivos preservados desde el inicio. El nuevo objeto debe identificarse como otro artefacto; no presentarlo como recuperación demostrada del binario oficial anterior. [GPLv3 §§1,5](https://www.gnu.org/licenses/gpl-3.0.html#section1).
